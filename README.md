# ESP32 speech-to-text

This repository contains an ESP32 + INMP441 microphone prototype that records while the BOOT button is held, streams a WAV-formatted request to Groq's Whisper-compatible transcription endpoint, and prints the transcript to the Arduino Serial Monitor.

## Current implementation status

Implemented in `CODES/CODESPACE/AI_STT_MAIN/AI_STT_MAIN.ino`:

- Wi-Fi station setup.
- INMP441 I2S receive at 16 kHz, mono, 32-bit I2S frames transformed to 16-bit samples.
- Two-stage high-pass filtering and digital gain.
- Streaming multipart WAV upload to `api.groq.com/openai/v1/audio/transcriptions`.
- `whisper-large-v3-turbo`, English, plain-text response.
- BOOT-button recording with a 15-second maximum.
- Transcript and diagnostic messages on serial at 115200 baud.

Not implemented in the current firmware:

- MAX98357/MAX98357A amplifier output.
- Speaker playback, text-to-speech, an LLM response, or a voice-assistant loop.
- Any amplifier pin assignment or I2S transmitter configuration.

The amplifier and 4-ohm speaker are therefore hardware reserved for a future output path; connecting them does not add audio output to the current sketch.

## Hardware and compatibility warning

The requested hardware is an original ESP32-S 38-pin CP2102 board. The main sketch, however, is labelled and configured in its source for an **ESP32-S3 Dev Module**. This repository does not contain evidence that the main sketch has been compiled or tested on the original ESP32-S board.

Before relying on the main sketch, confirm the exact board selected in Arduino IDE and verify that the installed ESP32 Arduino core exposes `ESP_I2S.h`, `I2SClass`, and `I2S_RX_TRANSFORM_32_TO_16`. The two microphone test sketches use the older `driver/i2s.h` API and are the safer first compatibility check for the original ESP32.

Do not use the S3-specific board settings as proof that they apply to the original ESP32. In particular, the main sketch's PSRAM and USB-CDC notes are S3-oriented. A CP2102 board normally uses its USB-to-serial bridge, but the exact Arduino serial setting should be confirmed for the board package and board selected.

## INMP441 wiring used by the repository

The following connections are explicitly defined by the microphone test sketches and the main sketch:

| INMP441 pin | ESP32 signal/pin | Function |
|---|---:|---|
| VDD | 3V3 | Microphone supply; the main sketch explicitly says not to use 5 V |
| GND | GND | Common ground |
| L/R | GND | Selects the left I2S channel |
| SD | GPIO 33 | Serial data from microphone |
| SCK | GPIO 26 | I2S bit clock generated by the ESP32 |
| WS | GPIO 25 | I2S word-select / LRCLK |

The board's BOOT button is expected at GPIO0 and is configured as active-low. No external button wiring is required by the current code.

### MAX98357/MAX98357A and speaker

The repository contains no MAX98357/MAX98357A wiring or transmitter code. Consequently, the exact ESP32 BCLK, LRCLK, DIN, power, and ground connections for the amplifier must not be inferred from this project. The 4-ohm 3 W speaker is not driven by the current firmware. A future audio-output implementation must document its I2S transmitter pins, sample format/rate, amplifier power arrangement, and speaker polarity before this section can be completed.

## Arduino IDE setup

1. Install the **esp32 by Espressif Systems** board package. The main sketch comments specify version `3.3.11` and the package URL `https://espressif.github.io/arduino-esp32/package_esp32_index.json`.
2. Open `CODES/CODESPACE/AI_STT_MAIN` as the sketch directory, or open `AI_STT_MAIN.ino` from that folder.
3. Copy `AI_STT_CONFIG_DEFAULT.h` to a new file named `AI_STT_CONFIG.h` in the same folder. Do not commit the copy with real credentials.
4. Fill in `SEED_WIFI_SSID`, `SEED_WIFI_PASS`, and `SEED_GROQ_KEY`.
5. Select the board that matches the physical hardware. The main sketch's checked-in setting is `ESP32S3 Dev Module`; this is not a validation of the original ESP32-S 38-pin board.
6. Select the CP2102 serial port and open Serial Monitor at **115200 baud**.
7. Upload and reset the board.

The main sketch has no external library dependency beyond the ESP32 board package. It includes `WiFi.h`, `WiFiClientSecure.h`, and `ESP_I2S.h`. ArduinoJson is not required because the request asks the transcription service for a plain-text response.

### Configuration values

The checked-in defaults are:

| Setting | Value | Meaning |
|---|---:|---|
| `SAMPLE_RATE` | 16000 | WAV and microphone sample rate |
| `MAX_SECONDS` | 15 | Recording hard stop |
| `SILENCE_PEAK` | 300 | Below this measured peak, reject as no signal |
| `HP_CUTOFF_HZ` | 120 | High-pass filter corner |
| `MIC_GAIN` | 6 | Digital gain after filtering |
| `PIN_BUTTON` | 0 | BOOT button, active low |
| `PIN_MIC_SD` | 33 | INMP441 SD |
| `PIN_MIC_SCK` | 26 | INMP441 SCK/BCLK |
| `PIN_MIC_WS` | 25 | INMP441 WS/LRCLK |
| `GROQ_HOST` | `api.groq.com` | HTTPS host |
| `STT_MODEL` | `whisper-large-v3-turbo` | Transcription model |

`WiFiClientSecure::setInsecure()` is used by the current code. The connection is encrypted, but the server certificate is not verified. Treat this as a prototype security limitation, not production TLS validation.

## Running the main sketch

After boot, wait for a line showing a Wi-Fi IP address and for the microphone status to report `started`.

1. Hold BOOT.
2. Speak toward the INMP441.
3. Release BOOT to stop, or allow the 15-second maximum to stop the recording.
4. Read `You said: ...` in Serial Monitor.

The sketch keeps a Groq connection warm while idle to reduce the delay after pressing BOOT. It sends audio while recording rather than buffering the complete clip first.

## Microphone-only tests

Use these before troubleshooting the cloud transcription path:

- `CODES/mic_test_1/mic_test_1.ino`: legacy I2S driver, GPIO 26/25/33, left channel, prints a block peak.
- `CODES/microphone_test/microphone_test.ino`: shorter legacy I2S test using the same pins, prints a block peak.

For either test, select the board that matches the physical board, upload, and open Serial Monitor at 115200. With a functioning microphone, the reported peak should change when you speak or make a sharp sound. The repository does not define a numeric pass/fail threshold for these tests.

## Troubleshooting

**`ESP_I2S.h: No such file or directory`**

The main sketch expects the newer ESP32 Arduino I2S API. The source says ESP32 core 2.x cannot build it. Install/use the board-package version expected by the sketch, or use a microphone-only legacy test while resolving the board/core compatibility.

**`I2S INIT FAILED`**

Check the selected board/core first, then verify INMP441 VDD is on 3V3, GND is common, L/R is tied to GND, and SD/SCK/WS use GPIO 33/26/25. The main sketch also contains S3-specific PSRAM guidance; do not assume that setting applies to an original ESP32 until tested.

**`[rec] no signal` or repeated polite/incorrect transcripts**

The firmware rejects a clip when its measured peak is below `SILENCE_PEAK`. Check microphone power, L/R selection, SD wiring, and the selected GPIOs. The code specifically warns that a transcription service may return plausible text for silence, so a transcript alone does not prove the microphone is wired correctly.

**Serial Monitor is blank**

Confirm 115200 baud, the correct CP2102 COM port, and that the selected board/USB serial setting matches the physical connection. The main sketch's USB-CDC comments distinguish a bridge port from an S3 native USB port; the original ESP32-S board should be treated as a bridge-port setup unless its documentation says otherwise.

**Wi-Fi connection never completes**

Check the copied `AI_STT_CONFIG.h` credentials and the availability of the configured Wi-Fi network. The current `setup()` waits indefinitely until Wi-Fi connects.

**HTTP 429 or another STT error**

Read the status and response printed after `[stt] HTTP`. HTTP 429 means rate limited according to the sketch. Confirm the Groq key, network access, endpoint availability, and account limits; the firmware does not implement retry/backoff for failed transcriptions.

**The amplifier/speaker is silent**

That is expected with the current code: it has no MAX98357 I2S transmitter or speaker playback path. Use the serial transcript as the only current output.

## Security and project limitations

- Keep `AI_STT_CONFIG.h` and API keys out of version control.
- The main sketch sends recorded speech to Groq for transcription.
- TLS certificate verification is disabled by `setInsecure()`.
- The code currently provides transcription only; it does not implement the speaker/assistant behavior described in the project goal.
